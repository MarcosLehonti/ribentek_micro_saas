🧾
Factura
Modelo: account.move
─────────────────────
suscripcion: Referencia (campo nuevo)
tipo: factura de cliente
origen: referencia de la orden
estado_pago: pagada / pendiente
lineas: N usuarios × precio
1 factura por cada evento de cobro
🛒
Orden de Venta
Modelo: sale.order
─────────────────────
suscripcion: Referencia (campo nuevo)
meses: Entero (campo nuevo)
cantidad_usuarios: Entero
tipo_orden: nueva / addon / renovacion
genera factura → activa suscripción
FÓRMULA DE COBRO:   Total = precio_plan × cantidad_usuarios × meses_elegidos // Ej: 100 Bs × 5 usuarios × 7 meses = 3,500 Bs
FECHA FIN:       fecha_fin = fecha_inicio + meses_pagados // cada usuario tiene sus propias fechas
SALIDA DE USUARIO: la línea queda vigente hasta fecha_fin → sin reembolso
NUEVO USUARIO:   nueva orden "addon" → nueva factura → nueva línea para ese usuario → independiente

Flujo para Agregar un Nuevo Usuario (Addon)
👁️
1. Detección Automática
El sistema compara cada día:
usuarios activos en instancia
vs líneas de suscripción activas

Si hay usuario sin línea →
se genera una alerta interna
ir.cron · diario · o hook en res.users
🔔
2. Aviso al Administrador
Email automático al admin:
"Nuevo usuario sin suscripción"
Nombre: Juan Pérez
Empresa: ABC S.R.L.
Enlace directo para pagar
mail.message · activity · portal link
🛒
3. Compra del Addon
Admin va al portal y configura:
・Para qué usuario
・Cuántos meses pagar
・Precio: N meses × 100 Bs
・Opción: sincronizar con el equipo
SO tipo = addon · subscription_id heredado
✅
4. Activar Usuario
Pago recibido → factura pagada:
→ Nueva línea de suscripción
→ fecha_inicio = hoy
→ fecha_fin = hoy + N meses
→ res.users.active = True
subscription.line.create() · acción automática
Ejemplo: Empresa ABC · Día 15 del Mes 4 — Nuevo empleado entra al equipo
# Contexto: 5 usuarios ya pagados por 7 meses desde el mes 1
# Hoy es el día 15 del mes 4. El jefe quiere agregar a María García.

nueva_orden = orden_venta.create({
    tipo_orden:           "addon",
    empresa_cliente:      empresa_abc,
    suscripcion_padre:    sub_abc,      # vincula con la suscripción existente
    usuario_nuevo:        maria_garcia,
    meses:               7,             # el jefe elige los mismos 7 meses
    total:               700 Bs        # 1 usuario × 7 meses × 100 Bs
})

# Al confirmar el pago se crea automáticamente:
nueva_linea = subscription_line.create({
    usuario:       maria_garcia,
    fecha_inicio: 15/mes4,
    fecha_fin:    15/mes11,      # fecha independiente del resto del equipo
    factura:      factura_addon,
    estado:       "activa"
})

# Resultado: el resto del equipo vence al final del mes 7
# María vence el día 15 del mes 11. Fechas independientes ✓
💡 Opción "Sincronizar con el equipo": Si el admin activa esta opción en el portal, el sistema calcula automáticamente los meses restantes hasta la fecha de vencimiento del grupo (Ej: el equipo vence en mes 7, faltan 3.5 meses → se cobran 4 meses → María vence en mes 8). Esto simplifica la gestión pero aumenta ligeramente el costo para el usuario nuevo.
5
Control de Vencimiento y Suspensión
⏰
Proceso Diario Automático
Se ejecuta todos los días:
Busca líneas donde
fecha_fin < hoy y estado = activa

Agrupa por suscripción
Decide qué acción tomar
según cuántas líneas venzan
ir.cron · todos los días medianoche
📢
Avisos de Vencimiento
30 días antes: correo informativo
15 días antes: correo urgente
7 días antes: correo + banner en portal
1 día antes: correo final al admin

Todos los avisos incluyen
botón directo de renovación
4 plantillas de correo · mail.template
🔴
Al Vencer: Bloqueo
Línea vencida:
→ línea.estado = expirada
→ res.users.active = False
  (el usuario no puede entrar)

Si toda la suscripción vence:
→ suscripcion.estado = pausada
→ datos preservados 30 días
acción automática · grace period 30 días
¿Cuántos usuarios
han vencido?
↙ Solo algunos
Suspensión Parcial
Solo se bloquean los usuarios
con línea vencida.
Los demás siguen activos.
Estado: parcialmente activa
state = parcialmente_activa
│
↘ Todos
Suspensión Total
Todos los usuarios bloqueados.
Estado: pausada
Instancia sigue corriendo.
Datos guardados 30 días.
state = pausada · grace period
⚠️
Después de 30 días sin renovar
1. Último aviso por email
   (incluye backup de datos)
2. Admin tiene opción de archivar
   o dar más tiempo al cliente
3. Si no hay respuesta:
   → Instancia detenida
   → Suscripción cancelada
   → Datos en backup por 90 días
4. Después de 90 días → eliminación definitiva
state = cancelada · política de retención

2. Elegir qué Renovar

3. Cálculo de Fechas
Si renueva antes de vencer:
nueva_fecha_inicio = fecha_fin_actual
(se acumula sin perder días)

Si renueva después de vencer:
nueva_fecha_inicio = fecha del pago
computed fields · lógica de acumulación
🟢
4. Reactivación
Factura pagada →
→ líneas de suscripción actualizadas
→ res.users.active = True
→ Estado: Activa
→ Email de confirmación al cliente
acción automática · on_payment

Estados de la Suscripción
Ciclo de vida completo — subscription.subscription.state
borrador
→
pago_pendiente
→
activa
→
parcialmente_activa
→
pausada
⟳
activa (renovada)
→
cancelada
borrador            → Orden de venta creada, sin pago todavía
pago_pendiente     → Orden confirmada, esperando recibir el pago
activa             → Todos los usuarios tienen líneas vigentes
parcialmente_activa → Algunos usuarios vigentes, otros ya vencieron
pausada           → Todos vencidos · acceso bloqueado · grace period 30 días
cancelada         → Sin renovación tras grace period · instancia archivada

REGLAS DE NEGOCIO CLAVE — NO OLVIDAR:
✓  Un usuario solo puede tener 1 línea activa por suscripción  // evitar cobro doble
✓  Al desactivar un usuario, la línea no se elimina  // ya fue cobrado, se guarda el registro
✓  Todo SO de tipo addon debe referenciar la suscripción padre  // trazabilidad completa
✓  La instancia solo puede tener usuarios ≤ suma(líneas activas)  // control de cupo
✓  Grace period de 30 días antes de bloquear instancia  // proteger datos del cliente
✗  Nunca eliminar datos sin backup previo y aviso al cliente  // política de retención de datos
